# Lab 6 – Exercise 1: Selected Use Cases

Three major use cases were selected for sequence-diagram modeling. Together they cover all three team members' components (Event Creation/Approval, Budget Requests, Accounts/Dashboard), and each involves multiple collaborating objects, non-trivial decision logic, and at least one iteration, which makes them representative of the system's core behavior.

| Use Case ID | Use Case Name | Primary Actor | Purpose | Reason for Selection |
|---|---|---|---|---|
| UC11 | Create Event Proposal (On-Campus) | President / Vice President (ClubMember with event-management permission) | Lets a club officer submit a new on-campus event proposal, which is automatically validated and checked against existing approved bookings for the requested room and date before being routed to the building's room allocator (faculty) for review. | Covers the Event Creation/Approval area (Haziq). It is one of the system's most complex flows: it involves client-side validation, object creation, a collaborating `ClashCheck` with an iteration over previously approved events, a conditional (guarded) branch for clash vs. no-clash, and a notification side-effect — a strong candidate for demonstrating both iteration (*) and guard [] notation. |
| UC07 | Review Budget Request | President (ClubMember with budget-decision permission) | Lets the president approve, reject, or send back (request changes to) a budget request submitted by the treasurer, creating a `BudgetDecisionRecord` and, on approval, allocating funds from the club's budget only if sufficient funds remain. | Covers the Budget Requests area (Abdelrahman). It is a three-way decision (mutually exclusive branches) with an additional nested guard (`sufficientFunds`) inside the approve branch, so it cleanly demonstrates `alt` fragments with explicit `[guard]` conditions and ties directly into `ClubBudget`'s derived `/remainingBalance` attribute. |
| UC02 | View Dashboard | Any Club Member (including role subclasses: President, Vice President, Executive, Treasurer) | Lets any logged-in club member retrieve a consolidated summary of their upcoming events, remaining club budget, and recent notifications in a single dashboard view. | Covers the Accounts/Roles/Notifications/Dashboard area (Ahmed). It is used by every actor type in the system regardless of role, and its logic is iteration-heavy (looping over the member's events and notifications to build filtered lists), making it the clearest place to demonstrate the `loop (*)` combined fragment together with nested `opt [guard]` filtering.
